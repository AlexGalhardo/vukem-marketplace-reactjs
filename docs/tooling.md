# Tooling

Every tool the project uses, with the command to run it. Prefer the narrowest command that proves your change.

| Tool | Purpose | Command |
| --- | --- | --- |
| Go 1.27 | Backend | `go build ./...`, `go vet ./...` |
| golangci-lint | Lint and format Go | `golangci-lint fmt`, `golangci-lint run ./...` |
| Go tests | Unit and HTTP-level tests (in-memory SQLite) | `go test -race ./...`, one package: `go test ./tests/catalog/ -run Suggest` |
| Integration tests | Real Postgres, Redis, MongoDB | `go test -tags integration ./tests/integration/...` with `TEST_DATABASE_URL`, `TEST_REDIS_URL`, `TEST_MONGO_URL` |
| govulncheck | Known vulnerabilities | `go tool govulncheck ./...` |
| Bun | JS package manager and runner (never npm or yarn) | `bun install`, `bun run <script>` |
| Biome | Lint and format TS/React | `bun run lint`, `bun run lint:fix` |
| TypeScript | Type check | `bun run typecheck` |
| Vite | Frontend build | `bun run build` |
| Playwright | End-to-end and accessibility specs | `bun run test:e2e` (stack on :3200, `bunx playwright install chromium` once) |
| markdownlint-cli2 | Markdown lint | `bun run lint:md` |
| lefthook | Git hooks (lint, commitlint) | installed by `bun install` |
| commitlint | Conventional Commits | `bunx commitlint --edit` (hook) |
| git-cliff | Changelog and releases | `git cliff --tag vX.Y.Z -o CHANGELOG.md` |
| ffmpeg | Regenerate the demo images | `go run internal/tools/genplaceholders/main.go` |
| Playwright video + ffmpeg | README GIFs in `docs/media` (stack up and seeded first) | `bun scripts/record-readme-gifs.ts [register, search, theme, checkout, chat or tests]` |
| Vukem CLI | `serve`, `migrate`, `db:seed`, `queue:work`, `route:list` | `vukem <command>` |

## Conventions

- Commits: Conventional Commits in English, with a scope (`feat(catalog): ...`). See `.claude/rules/commits.md`.
- `CHANGELOG.md` is generated by git-cliff from the commit messages; never edit it by hand.
- Indentation: tabs of width 4 (`.editorconfig`), except YAML and Markdown.
- Vukem is pinned by tag in `go.mod`; framework findings go to [vukem-feedback.md](../vukem-feedback.md).

## Working with coding agents

Start every session by loading the `karpathy-guidelines` skill, caveman mode and `graphify` (`graphify query "<question>"` before reading many files; `graphify update .` when the graph is stale). The rules in `.claude/rules/` load by path; [AGENTS.md](../AGENTS.md) lists the commands.
